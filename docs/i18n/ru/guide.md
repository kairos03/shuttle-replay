# Руководство пользователя shuttle-replay (v0.1)

`shuttle-replay` это офлайн-инструмент, который строит повтор полёта волана в
бадминтоне из локального видео, уже подготовленных вами детекций и разметки,
проверенной человеком. Он калибрует камеру, подгоняет к 2D-координатам
детекций модель полёта с гравитацией и квадратичным сопротивлением воздуха и
создаёт MP4, в котором исходное видео и вид корта сверху расположены рядом в
пропорции 6:4.

Инструмент предназначен для исследований и разбора. Это не система судейства
линий аут/ин, не классификатор ударов, не детектор волана и не измерительный
радар скорости. Каждая 3D-позиция и скорость в выходных данных является
условным значением модели, которое предполагает вашу калибровку и разметку.

## Установка

Требуются Python 3.12 или новее и [uv](https://docs.astral.sh/uv/).

```bash
git clone https://github.com/KAIROS03/shuttle-replay
cd shuttle-replay
uv sync
uv run shuttle-replay --help
```

Колёса PyAV содержат FFmpeg, поэтому системный FFmpeg не требуется.

## Синтетическое демо

```bash
uv run shuttle-replay demo --out-dir demo
```

Команда строит синтетический розыгрыш, в котором смешаны две виртуальные
камеры, переходный сегмент и пропущенные детекции, а затем выполняет
калибровку → анализ → рендеринг от начала до конца. Значения в
`demo/synthetic_recovery.json` сравниваются с синтетическими эталонными
данными, поэтому они не показывают точность на реальном видео.

## Работа с собственным видео

1. **Детекции (`tracks.json`)**: одна строка на каждый декодированный кадр с
   фактическим PTS этого кадра (в секундах), id сегмента камеры (`null` для
   переходных сегментов и крупных планов), пиксельными координатами волана
   (`null`, если его нет) и необязательными рамками игроков. `frame_id` должен
   соответствовать порядку декодирования. Формат описан в
   [docs/schemas.md](schemas.md).
   В v0.1 нет детектора. Вы можете сами запустить TrackNetV3 (MIT) или
   Ultralytics YOLO (AGPL-3.0) и преобразовать результаты, но скрипт
   преобразования не входит в комплект. Никакие веса моделей не загружаются.
2. **Входные данные калибровки**: для каждого сегмента камеры отметьте в
   пикселях четыре или более пересечения линий корта (`fit`), несколько
   пересечений для проверки (`heldout`) и две верхушки стоек сетки (высота
   1.55 м).

   ```bash
   uv run shuttle-replay calibrate calibration_input.json -o calibration.json
   ```

   Сначала проверьте `heldout_summary` (ошибку на точках, не использованных при
   подгонке) и `net_anchor_sensitivity` (насколько смещается высота, если
   стойки сетки сдвинуть на заданную ошибку в пикселях). Гомография пола
   используется только для точек на полу (Z=0) и никогда для волана в воздухе.
3. **Разметка проверки (`review.json`)**: укажите время касания ракеткой
   (`time_s`), интервал проверки, который его содержит (`time_bracket_s`),
   пиксель касания и оценку высоты. Время касания является нулевой секундой
   полёта. Поздняя первая детекция не меняет нулевую секунду.
   Условие завершения может быть только у последнего касания сегмента:
   `landing_region` (область и временной интервал, в которых волан достигает
   пола) или `open` (до последнего наблюдения в сегменте или до проверенного
   `until_s`). Любой другой полёт заканчивается на следующем касании и не
   принуждается достигать пола. v0.1 не исправляет время касаний
   автоматически, поэтому исправляйте его сами, просматривая кадры.
4. **Анализ и рендеринг**

   ```bash
   uv run shuttle-replay analyze --tracks tracks.json --review review.json \
       --calibration calibration.json -o analysis.json
   uv run shuttle-replay render --video match.mp4 --analysis analysis.json -o replay.mp4
   # 한 번에:
   uv run shuttle-replay run --video match.mp4 --tracks tracks.json --review review.json \
       --calibration calibration.json --out-dir out
   ```

   Комментарий `# 한 번에:` означает «всё за один шаг:»; `run` выполняет
   анализ и рендеринг вместе.

   Инструмент завершается с кодом выхода 2, если PTS идёт назад, если тот же
   сегмент камеры появляется снова после разрыва, если касание лежит вне
   своего сегмента камеры или интервала проверки, или если PTS видео и PTS
   треков различаются. Он никогда не исправляет входные данные молча.

## Как читать результаты

- Зелёный круг: входные координаты детекции в исходном виде. Кадры без
  детекции остаются пустыми.
- Оранжевый круг/точки: условная физическая модель. Рисуется только внутри
  одного сегмента камеры и одного полёта.
- Синяя пунктирная рамка: зона приземления, указанная человеком. Знак ×
  является точкой приземления модели, подогнанной с этой зоной в качестве
  условия, а не измеренной координатой.
- Скорость является начальной скоростью модели, округлённой до 5 км/ч.
- Для отбитого полёта точка «куда бы он приземлился, если бы его не отбили»
  записывается только в JSON (`unreturned_floor_crossing_prediction`,
  контрфактический прогноз).
- Если в исходнике есть звук, аудиопакеты копируются как есть без
  перекодирования, поэтому задержка начала звука и пропуски исходника
  сохраняются. Если звук нельзя скопировать в MP4 или его тайминг изменился
  бы, рендеринг завершается ошибкой. Результат проверочного декодирования
  выходного файла до конца записывается в `render_report.json`.
- Существующие файлы никогда не перезаписываются. Инструмент останавливается,
  если выходной файл уже существует или является тем же файлом, что и
  исходное видео, а рендеринг пишет во временный файл, который переименовывается
  в итоговое имя только после проверки.
