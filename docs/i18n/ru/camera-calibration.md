# Калибровка камеры

Калибровка отвечает на один вопрос: в каком пикселе камера показывает точку
корта, заданную в метрах? `shuttle-replay` отвечает на него линейной моделью
камеры-обскуры, оценённой по точкам, которые вы нашли вручную. Эта страница
объясняет системы координат, две матрицы, которые вычисляет инструмент, точный
алгоритм и смысл сообщаемых ошибок.

## Две системы координат

**Координаты изображения** `(u, v)` это пиксели исходного видео: `u` растёт
вправо, `v` растёт вниз.

**Мировые координаты** `(X, Y, Z)` это метры в системе корта, заданной
размерами корта BWF
([`court.py`](https://github.com/KAIROS03/shuttle-replay/blob/6e9a060b5cc964f02d4017d806e953ffea89c8b4/src/shuttle_replay/court.py#L1-L24)):

```text
      X = 0                X = 6.10
 Y = 0  +--------------------+   far baseline (outer edge)
        |                    |
        |                    |
 Y=6.70 |====== net =========|   net plane; posts 1.55 m, centre 1.524 m
        |                    |
        |                    |
Y=13.40 +--------------------+   near baseline (outer edge)

 Z is up; Z = 0 is the court surface.
```

Линии имеют ширину 40 мм, и точки калибровки используют **центры линий**:
внешние линии при X = 0.02 / 6.08 и Y = 0.02 / 13.38, боковые линии одиночной
игры при X = 0.48 / 5.62, короткие линии подачи при Y = 4.70 / 8.70, длинные
линии подачи парной игры при Y = 0.78 / 12.62, центральная линия X = 3.05
([`court_lines`](https://github.com/KAIROS03/shuttle-replay/blob/6e9a060b5cc964f02d4017d806e953ffea89c8b4/src/shuttle_replay/court.py#L27-L52)).
Если ввести внешний край там, где ожидается центр, точка сместится на 2 см.

## Проекция камеры-обскуры

Камера-обскура отображает мировую точку в пиксель матрицей 3x4 `P`:

```text
 [a]       [X]
 [b] = P * [Y]        u = a / c ,  v = b / c
 [c]       [Z]
           [1]
```

Деление на `c` даёт перспективу: далёкие предметы выглядят маленькими. `P`
объединяет положение и поворот камеры (внешние параметры) с её фокусным
расстоянием и центром изображения (внутренние параметры). Проект никогда не
разлагает `P` на эти части; он использует `P` как одну матрицу
([`project`](https://github.com/KAIROS03/shuttle-replay/blob/6e9a060b5cc964f02d4017d806e953ffea89c8b4/src/shuttle_replay/geometry.py#L12-L15)).
Центр камеры `C` это единственная точка, для которой `P * [C, 1] = 0`, поэтому
`C = -inverse(P[:, :3]) * P[:, 3]`
([`camera_center`](https://github.com/KAIROS03/shuttle-replay/blob/6e9a060b5cc964f02d4017d806e953ffea89c8b4/src/shuttle_replay/geometry.py#L24-L26)).

## Шаг 1: гомография пола (только Z = 0)

Для точек на полу `Z = 0`, поэтому третий столбец `P` умножается на ноль и
выпадает:

```text
 P = [ p1  p2  p3  p4 ]          (four columns)
 floor point (X, Y, 0):  P * [X, Y, 0, 1] = [ p1 p2 p4 ] * [X, Y, 1] = H * [X, Y, 1]
```

Матрица 3x3 `H = [p1 p2 p4]` является **гомографией**. Она подгоняется по
вашим наземным точкам с `role: "fit"` нормализованным прямым линейным
преобразованием (DLT) в
[`fit_homography`](https://github.com/KAIROS03/shuttle-replay/blob/6e9a060b5cc964f02d4017d806e953ffea89c8b4/src/shuttle_replay/calibration.py#L58-L78):

1. Каждый набор точек сдвигается к своему центроиду и масштабируется так, чтобы
   среднее расстояние до центроида было `sqrt(2)`
   ([`_normalize`](https://github.com/KAIROS03/shuttle-replay/blob/6e9a060b5cc964f02d4017d806e953ffea89c8b4/src/shuttle_replay/calibration.py#L36-L39)).
   Это сохраняет хорошую обусловленность линейной системы, когда значения
   пикселей исчисляются сотнями, а метры однозначными числами.
2. Каждое соответствие добавляет две строки в линейную систему `A h = 0`.
3. `h` это правый сингулярный вектор `A` для наименьшего сингулярного числа;
   нормализация отменяется, и `H` масштабируется так, чтобы `H[2, 2] = 1`.

Вырожденные входные данные отклоняются с `CalibrationError` вместо того, чтобы
давать плохую матрицу: меньше четырёх точек подгонки, дублирующиеся
координаты, коллинеарные наборы точек, три коллинеарные точки из ровно четырёх,
второе наименьшее сингулярное число ниже `1e-9` от наибольшего (решение не
единственно) или число обусловленности выше `1e12`
([`_check_spread`](https://github.com/KAIROS03/shuttle-replay/blob/6e9a060b5cc964f02d4017d806e953ffea89c8b4/src/shuttle_replay/calibration.py#L42-L78)).

Подгонка является нормализованным DLT, минимизирующим алгебраическую невязку
по всем точкам подгонки, без нелинейного уточнения по ошибке репроекции. Нет
отбраковки выбросов (нет RANSAC) и нет модели дисторсии объектива: опечатка в
одной точке или сильная бочкообразная дисторсия тянет всю подгонку.

`H` описывает только пол. Вывод говорит об этом в `H_scope`
([`H_SCOPE`](https://github.com/KAIROS03/shuttle-replay/blob/6e9a060b5cc964f02d4017d806e953ffea89c8b4/src/shuttle_replay/calibration.py#L22)).
Обратная проекция пикселя волана через `H` отвечает на вопрос «где был бы этот
пиксель, если бы он лежал на полу», что неверно для всего, что находится в
воздухе.

## Шаг 2: вертикальный столбец по якорям сетки

Точки пола ничего не говорят о `p3`, столбце, который умножается на высоту.
Для него нужны точки известной высоты, не лежащие на полу: обычно две вершины
стоек сетки при `Z = 1.55`. Для якоря в `(X, Y, Z)`, видимого в `(u, v)`,
запишем `q = H * [X, Y, 1]`. Условие проекции становится линейным по `p3`:

```text
 u * (q3 + Z * p3_3) = q1 + Z * p3_1
 v * (q3 + Z * p3_3) = q2 + Z * p3_2

 rearranged per anchor:
   [ Z  0  -u*Z ] * p3 = u*q3 - q1
   [ 0  Z  -v*Z ] * p3 = v*q3 - q2
```

[`camera_from_anchors`](https://github.com/KAIROS03/shuttle-replay/blob/6e9a060b5cc964f02d4017d806e953ffea89c8b4/src/shuttle_replay/calibration.py#L81-L92)
складывает эти строки, требует ранга 3, решает методом наименьших квадратов и
собирает `P = [h1 h2 p3 h3]`, где `h1`, `h2`, `h3` это столбцы `H`. Три
неизвестных и две строки на якорь означают, что два якоря дают четыре
уравнения: система почти точно определена. Поэтому малая невязка якорей
(`net_anchor_residuals_px`) доказывает немногое. Якоря должны быть подняты
(`Z > 0.1 m`), и их должно быть не меньше двух.

Наконец,
[`_check_camera`](https://github.com/KAIROS03/shuttle-replay/blob/6e9a060b5cc964f02d4017d806e953ffea89c8b4/src/shuttle_replay/calibration.py#L95-L104)
отклоняет камеру, центр которой не находится над полом, или камеру, для
которой одни точки корта оказались бы перед ней, а другие позади.

## Точки подгонки и отложенные точки

У каждой наземной точки есть роль
([`calibrate_segment`](https://github.com/KAIROS03/shuttle-replay/blob/6e9a060b5cc964f02d4017d806e953ffea89c8b4/src/shuttle_replay/calibration.py#L128-L205)):

- Точки `fit` строят `H`. Их невязки (`fit_ground_residuals`) являются
  ошибкой обучения и должны быть малыми.
- Точки `heldout` никогда не используются для подгонки. Нужна хотя бы одна.
  `heldout_ground_errors` сообщает для каждой точки `error_px` (`H`,
  применённая к мировой точке, в сравнении с вашим пикселем) и `error_m`
  (обратная `H`, применённая к вашему пикселю, в сравнении с мировой точкой).
  `heldout_summary` даёт количество, среднее и максимум обеих величин.

Концептуальный пример: четыре внешних угла как `fit` и два пересечения линий
подачи как `heldout`. Если ошибки отложенных точек намного больше невязок
подгонки, значит, какая-то точка помечена неверно, щёлкнули по краю линии
вместо её центра или объектив искривляет линии. Ошибка отложенных точек
проверяет только отображение пола; о высотах она ничего не говорит.

## Чувствительность, а не доверительный интервал

Высоты почти полностью зависят от якорей.
[`_anchor_sensitivity`](https://github.com/KAIROS03/shuttle-replay/blob/6e9a060b5cc964f02d4017d806e953ffea89c8b4/src/shuttle_replay/calibration.py#L107-L125)
берёт опорную точку `(3.05, 6.70, 3.0)`, на 3 м выше центральной линии сетки,
и проецирует её с помощью `P`. Затем для каждого якоря и отдельно для `u` и
`v` она сдвигает пиксель якоря на `+uncertainty_px` и `-uncertainty_px` (по
умолчанию 3.0), заново решает `P` и пересекает луч через тот же опорный
пиксель с плоскостью сетки `Y = 6.70`. `max_vertical_shift_m` это наибольшее
изменение высоты. Если возмущение приводит к сбою решения, сдвиг сообщается
как бесконечность.

Это худший случай для одной точки при изменении по одному параметру за раз.
Это не статистический доверительный интервал, он не объединяет ошибки
нескольких якорей и не учитывает ошибку наземных точек.

## Допущения, которые вы делаете

- Одна неподвижная камера на `segment_id`; сдвиг камеры или зум требует нового
  сегмента.
- Прямые линии остаются прямыми на изображении (нет дисторсии объектива).
- Якоря имеют те высоты, которые вы вводите. Вершины стоек на 1.55 м и центр
  сетки на 1.524 м это разные высоты.
- Плоскость пола это не волан. `H` даёт позиции на полу; глубина волана
  берётся только из физической подгонки, описанной в
  [Физика траектории](trajectory-physics.md).

Полный список входных и выходных полей см. в [схемах](schemas.md), а о том, как
читать ошибки вместе с диагностикой полётов, см.
[Валидация и ограничения](validation-limits.md).
