# Форматы входных и выходных данных (v0.1)

Все координаты в метрах заданы в системе корта: X поперёк корта и Y вдоль
него, внешняя граница корта (внешние края граничных линий) находится при
X = 0 .. 6.10 и Y = 0 (дальняя сторона) .. 13.40 (ближняя сторона); Z вверх
(0 = пол). Плоскость сетки Y = 6.70. Ширина линий 40 мм; вводите точки на
полу по центрам линий: внешние линии X = 0.02 / 6.08 и Y = 0.02 / 13.38,
боковые линии одиночной игры X = 0.48 / 5.62, передние линии подачи
Y = 4.70 / 8.70, задние линии подачи парной игры Y = 0.78 / 12.62, центральная
линия X = 3.05.
Координаты изображения задаются в пикселях исходного видео (x вправо, y вниз).
Время задаётся временными метками представления исходника (PTS) в секундах в
том виде, в каком их декодирует FFmpeg/PyAV (`frame.pts * time_base`), и
никогда как `frame_index / fps`.

Запустите `shuttle-replay demo --out-dir demo`, чтобы получить в
`demo/inputs/` полный синтетический пример каждого файла, описанного ниже.

## Входные данные калибровки — `shuttle-replay/calibration-input/v1`

```json
{
  "schema": "shuttle-replay/calibration-input/v1",
  "segments": [
    {
      "segment_id": 0,
      "image_size": [1280, 720],
      "ground_points": [
        {"name": "far_left_corner", "world_m": [0.02, 0.02], "image_px": [412.0, 188.5], "role": "fit"},
        {"name": "single_left_x_short_far", "world_m": [0.48, 4.70], "image_px": [430.1, 260.2], "role": "heldout"}
      ],
      "net_anchors": [
        {"name": "left_post_top", "world_m": [0.0, 6.7, 1.55], "image_px": [380.2, 250.0], "uncertainty_px": 3.0}
      ]
    }
  ]
}
```

- Точки `role: "fit"` (≥ 4, не коллинеарные, без дубликатов) оценивают
  гомографию пола. Точки `role: "heldout"` (≥ 1) никогда не участвуют в
  подгонке и выводятся отдельно как ошибки на отложенных точках в пикселях и
  метрах.
- `net_anchors` (≥ 2, Z > 0.1 м) восстанавливают вертикальный столбец матрицы
  камеры. При ровно двух опорных точках столбец определяется почти точно,
  поэтому их невязка мало о чём говорит; выходные данные содержат отчёт о
  чувствительности (вертикальное смещение точки на 3 м выше сетки при сдвиге
  опорной точки на `uncertainty_px`).
- Неконечные числа, коллинеарные/дублирующиеся точки подгонки, опорные точки
  на уровне пола и камеры ниже пола отклоняются.

Выходные данные (`shuttle-replay/calibration/v1`) содержат для каждого
сегмента `P` (3×4, метры → пиксели), `H_world_to_image` / `H_image_to_world`
(только пол), `fit_ground_residuals`, `heldout_ground_errors`,
`heldout_summary`, `net_anchor_residuals_px`, `net_anchor_sensitivity` и копию
входных данных.

## Треки — `shuttle-replay/tracks/v1`

```json
{
  "schema": "shuttle-replay/tracks/v1",
  "source_video": "match.mp4",
  "frames": [
    {"frame_id": 0, "pts_s": 0.0, "segment_id": 0,
     "shuttle": {"u": 315.3, "v": 265.6, "score": 0.91},
     "players": [{"label": "near", "box": [339.8, 350.1, 408.4, 521.7], "score": 0.9}]},
    {"frame_id": 1, "pts_s": 0.0333, "segment_id": 0, "shuttle": null, "players": []}
  ]
}
```

- Одна запись на каждый декодированный кадр исходника в порядке
  декодирования; `frame_id` должен совпадать с индексом декодирования
  (рендерер проверяет это и PTS каждого кадра).
- `frame_id` и `pts_s` должны строго возрастать и быть конечными.
- `segment_id` обозначает непрерывный план камеры, для которого есть
  калибровка; `null` помечает смены плана / крупные планы / повторы, которые
  исключаются. Сегмент должен быть непрерывным; id сегмента, который снова
  появляется после другого сегмента, отклоняется (дайте более позднему плану
  собственный id и калибровку).
- `shuttle: null` означает «нет детекции». Это значение остаётся null во всех
  выходных данных.

## Разметка проверки — `shuttle-replay/review/v1`

```json
{
  "schema": "shuttle-replay/review/v1",
  "physics": {"pixel_sigma_px": 3.0, "contact_guard_s": 0.02},
  "contacts": [
    {"id": "c1", "segment_id": 0, "time_s": 0.20, "time_bracket_s": [0.16, 0.24],
     "image_px": [402.0, 300.0], "height_m": 1.05, "height_sigma_m": 0.3,
     "review": "racket contact visible"}
  ],
  "flight_ends": [
    {"contact_id": "c5", "type": "landing_region", "time_bracket_s": [5.1, 5.4],
     "region_xy_m": {"min": [4.2, 0.8], "max": [4.9, 1.6]}, "review": "lands IN"},
    {"contact_id": "c3", "type": "open", "review": "camera cuts away mid-flight"}
  ]
}
```

- Касания являются проверенными касаниями ракеткой. `time_s` это проверенная
  временная метка касания, она становится нулевым временем полёта, даже если
  первая детекция волана появляется позже. Она должна лежать внутри своего
  сегмента камеры и внутри `time_bracket_s` (шириной ≤ 0.5 с). Касания в
  сегменте должны строго возрастать. v0.1 не уточняет время касаний
  автоматически; уточняйте его, просматривая кадры и редактируя `time_s`.
- Априорная позиция: `image_px` (проверенный пиксель касания, пересечённый с
  плоскостью Z = `height_m` через полную матрицу камеры P) или `court_xy_m`.
  `height_m` является проверенным априорным значением с `height_sigma_m`;
  `xy_sigma_m` необязателен (по умолчанию 0.5 м).
- Полёт длится от касания до следующего касания того же сегмента
  (`intercepted_by_next_contact`, никогда не принуждается к полу). Только
  последнее касание сегмента может иметь запись `flight_ends`:
  `landing_region` (контакт с полом ограничен проверенной рамкой внутри
  временного интервала) или `open` (подгонка до последнего наблюдения в
  сегменте или до необязательного проверенного `until_s`). Отсутствие записи =
  open.
- Ключи `physics` (все необязательны): `gravity_m_s2`, `pixel_sigma_px`,
  `drag_prior_per_m`, `drag_prior_sigma`, `drag_bounds_per_m`,
  `contact_guard_s`, `contact_xy_sigma_m`, `min_observations`,
  `max_accept_rms_px`, `velocity_bound_m_s`.

## Выходные данные анализа — `shuttle-replay/analysis/v1`

- `flights[]`: `t0_s` (проверенное касание), `t_end_s`, `end_type`, `params`
  (`[x, y, z, vx, vy, vz, drag_k]` в момент касания), `fit` (RMS / p90 / max
  репроекции в пикселях, число наблюдений, статус оптимизатора), `gates`
  (допустимость относительно пола и сетки; высота над сеткой ≥ 1.524 м, когда
  полёт пересекает сетку), `parameters_at_bound` (подгонка, упёршаяся в
  границу оптимизатора, отклоняется), `accepted`, `model_speed_km_h` и
  `model_speed_coarse_km_h`, `first_observation_delay_s`,
  `observation_frame_ids`, `landing` (полёты с приземлением;
  `exact_coordinate_measured: false`) и
  `unreturned_floor_crossing_prediction` (перехваченные/открытые полёты;
  `kind: counterfactual_if_unreturned`, `observed: false`).
- `frames[]`: `shuttle_observed_px` (переданная детекция или null),
  `shuttle_model_xyz_m` / `shuttle_model_px` (только принятая модель, тот же
  сегмент), `model_flight_id`, `layer` (`conditional_model`, `observed_pixel`,
  `none`, `excluded_camera_cut`).
- `provenance_vocabulary`, `assumptions`, `calibration_summary`.

## Отчёт о рендеринге

`render_report.json` фиксирует энкодер, число кадров, максимальную разницу
между декодированным PTS исходника и PTS трека, раскладку 6:4, сохранён ли
звук, а также результат полного декодирования записанного MP4.
