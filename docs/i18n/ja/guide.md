# shuttle-replay ユーザーガイド (v0.1)

`shuttle-replay` は、ローカル動画、あなたが事前に作成した検出結果、人がレビューしたアノテーションから、バドミントンのシャトルリプレイを作成するオフラインツールです。カメラをキャリブレーションし、重力と二次空気抵抗を含む飛行モデルを 2D 検出座標にフィッティングし、元動画と俯瞰コート図を 6:4 で左右に並べた MP4 を作成します。

このツールは研究とレビューのためのものです。イン/アウトのライン判定システム、ショット分類器、シャトル検出器、実測のスピードガンではありません。出力に含まれるすべての 3D 位置と速度は、あなたのキャリブレーションとアノテーションを前提とした条件付きのモデル値です。

## インストール

Python 3.12 以降と [uv](https://docs.astral.sh/uv/) が必要です。

```bash
git clone https://github.com/KAIROS03/shuttle-replay
cd shuttle-replay
uv sync
uv run shuttle-replay --help
```

PyAV の wheel には FFmpeg が同梱されているため、システムの FFmpeg は必要ありません。

## 合成デモ

```bash
uv run shuttle-replay demo --out-dir demo
```

2 台の仮想カメラ、切り替え区間、検出の欠落を組み合わせた合成ラリーを作成し、キャリブレーション → 解析 → レンダリングを最後まで実行します。`demo/synthetic_recovery.json` の値は合成の正解値と比較したものなので、実際の動画での精度を示すものではありません。

## 自分の動画を使う

1. **検出結果（`tracks.json`）**：デコードされたフレームごとに 1 行で、そのフレームの実際の PTS（秒）、カメラセグメント id（切り替え区間やクローズアップ区間では `null`）、シャトルのピクセル座標（存在しない場合は `null`）、任意の選手ボックスを記述します。`frame_id` はデコード順と一致している必要があります。形式は [docs/schemas.md](schemas.md) を参照してください。
   v0.1 には検出器がありません。TrackNetV3 (MIT) や Ultralytics YOLO (AGPL-3.0) を自分で実行して結果を変換することはできますが、変換スクリプトは同梱されていません。モデルの重みはダウンロードされません。
2. **キャリブレーション入力**：カメラセグメントごとに、4 点以上のコートラインの交点（`fit`）、検証用のいくつかの交点（`heldout`）、2 本のネットポストの上端（高さ 1.55 m）をピクセルで指定します。

   ```bash
   uv run shuttle-replay calibrate calibration_input.json -o calibration.json
   ```

   まず `heldout_summary`（フィッティングに使っていない点での誤差）と `net_anchor_sensitivity`（ネットポストを指定したピクセル誤差だけずらしたときに高さがどれだけ動くか）を確認してください。床面ホモグラフィは床面（Z=0）上の点にのみ使用され、空中のシャトルには決して使用されません。
3. **レビューアノテーション（`review.json`）**：ラケットの打点時刻（`time_s`）、それを含むレビュー区間（`time_bracket_s`）、打点のピクセル、高さの推定値を入力します。打点時刻がその飛行の 0 秒になります。最初の検出が遅れても 0 秒は変わりません。
   終了条件を持てるのはセグメントの最後の打点だけです。`landing_region`（シャトルが床に到達する領域と時間区間）または `open`（セグメントの最後の観測まで、あるいはレビューで指定した `until_s` まで）です。それ以外の飛行は次の打点で終わり、床への到達を強制されません。v0.1 は打点時刻を自動で補正しないため、フレームを見ながら自分で修正してください。
4. **解析とレンダリング**

   ```bash
   uv run shuttle-replay analyze --tracks tracks.json --review review.json \
       --calibration calibration.json -o analysis.json
   uv run shuttle-replay render --video match.mp4 --analysis analysis.json -o replay.mp4
   # 한 번에:
   uv run shuttle-replay run --video match.mp4 --tracks tracks.json --review review.json \
       --calibration calibration.json --out-dir out
   ```

   `# 한 번에:` というコメントは「一度にまとめて：」という意味で、`run` は解析とレンダリングを一緒に実行します。

   PTS が逆戻りする場合、同じカメラセグメントが間を空けて再登場する場合、打点がそのカメラセグメントやレビュー区間の外にある場合、動画の PTS とトラックの PTS が異なる場合、ツールは終了コード 2 で停止します。入力を黙って修正することはありません。

## 結果の読み方

- 緑の円：与えられたままの入力検出座標です。検出のないフレームは空のままです。
- オレンジの円/点：条件付き物理モデルです。同じカメラセグメントかつ同じ飛行の中でのみ描画されます。
- 青い破線の枠：人が指定した着地領域です。× 印はその領域を条件としてフィッティングしたモデルの着地点であり、実測座標ではありません。
- 速度はモデルの初速を 5 km/h 単位で丸めたものです。
- 返球された飛行について、「返球されなかったらどこに落ちていたか」の点は JSON にのみ記録されます（`unreturned_floor_crossing_prediction`、反実仮想の予測）。
- 元動画に音声がある場合、音声パケットは再エンコードせずにそのままコピーされるため、元動画の音声の開始遅延や途切れは保持されます。音声を MP4 にコピーできない場合や、タイミングが変わってしまう場合、レンダリングは失敗します。検証のために出力ファイルを最後までデコードした結果は `render_report.json` に書き込まれます。
- 既存のファイルが上書きされることはありません。出力ファイルがすでに存在する場合や元動画と同じファイルである場合、ツールは停止します。レンダリングは一時ファイルに書き込み、検証が済んでから最終的なファイル名に移動します。
