## Обзор

`shuttle-replay` калибрует камеру по проверенным вами точкам корта, подгоняет
траектории полёта с гравитацией и квадратичным сопротивлением воздуха к
предоставленным вами 2D-детекциям волана и рендерит MP4, где исходное видео
стоит рядом с видом корта сверху.

Это инструмент для исследований и проверки, а не система судейства линий,
классификатор ударов, детектор волана или измерительный 3D-радар скорости.
Каждая 3D-позиция и скорость являются условным выходом модели, который зависит
от вашей калибровки и разметки.

## Установка

Требуются Python 3.12+ и [uv](https://docs.astral.sh/uv/).

```bash
git clone https://github.com/KAIROS03/shuttle-replay
cd shuttle-replay
uv sync
uv run shuttle-replay --help
```

Колёса PyAV включают FFmpeg, поэтому системный FFmpeg не нужен.

## Зачем это нужно

- **Полностью офлайн.** Нет детектора, нет весов моделей, нет сетевых запросов.
- **Сначала проверка человеком.** Контакты, зоны приземления и точки калибровки задаёте вы; ничто не исправляется молча.
- **Честное разделение слоёв.** Наблюдаемые пиксели, ваша проверка и условная модель хранятся в выходных данных раздельно.
- **Безопасный рендеринг.** Исходное аудио копируется потоком без перекодирования, а существующие файлы никогда не перезаписываются.

<a id="quick-start"></a>
## Быстрый старт

```bash
uv run shuttle-replay demo --out-dir demo
```

Записывает `demo/inputs/` (синтетическое видео, треки, проверка, входные данные калибровки),
`demo/calibration.json`, `demo/analysis.json`, `demo/replay.mp4`,
`demo/render_report.json` и `demo/synthetic_recovery.json`.

<a id="workflow"></a>
## Порядок работы

Что нужно предоставить для вашего собственного видео:

- **Детекции** (`tracks.json`): одна запись на каждый декодированный кадр с PTS,
  идентификатором сегмента камеры, пикселем волана или null и необязательными
  рамками игроков. Встроенного детектора нет.
- **Входные данные калибровки**: для каждого сегмента не менее 4 точек корта
  `fit`, несколько точек `heldout` и верхушки обеих стоек сетки (1,55 м).
- **Проверка** (`review.json`): проверенные вами моменты, пиксели и высоты
  контактов, а также необязательные зоны приземления. Контакты не находятся
  автоматически.

```bash
uv run shuttle-replay calibrate calibration_input.json -o calibration.json
uv run shuttle-replay run --video match.mp4 --tracks tracks.json --review review.json \
    --calibration calibration.json --out-dir out
```

<a id="user-guide"></a>

<details>
<summary><b>Пошаговое руководство для вашего видео</b></summary>

1. **Детекции.** Создайте по одной записи `tracks.json` на каждый декодированный
   кадр с PTS кадра, идентификатором сегмента камеры (null для склеек и крупных
   планов), пикселем волана (или null) и необязательными рамками игроков. См.
   [docs/schemas.md](docs/schemas.md) (на английском).
   Подойдёт любой трекер; например, вы можете сами запустить TrackNetV3 (MIT)
   для волана и модель Ultralytics YOLO (AGPL-3.0) для игроков со своими
   чекпойнтами и преобразовать их выходные данные. Скрипты преобразования не
   входят в v0.1.
2. **Входные данные калибровки.** Для каждого сегмента камеры измерьте ≥ 4
   пересечения линий корта (роль `fit`), ещё несколько как `heldout` и верхушки
   двух стоек сетки (1,55 м).

   ```bash
   uv run shuttle-replay calibrate calibration_input.json -o calibration.json
   ```

   Прежде чем продолжать, проверьте `heldout_summary` и `net_anchor_sensitivity`.
3. **Проверка.** Напишите `review.json`: моменты контактов внутри проверенных
   интервалов, априорные значения пикселя и высоты контакта, а для последнего
   полёта сегмента необязательную зону приземления или `open`.
4. **Анализ и рендеринг.**

   ```bash
   uv run shuttle-replay analyze --tracks tracks.json --review review.json \
       --calibration calibration.json -o analysis.json
   uv run shuttle-replay render --video match.mp4 --analysis analysis.json -o replay.mp4
   # or both at once:
   uv run shuttle-replay run --video match.mp4 --tracks tracks.json --review review.json \
       --calibration calibration.json --out-dir out
   ```

   Несогласованные входные данные (немонотонные PTS, несмежные сегменты,
   контакты вне своего сегмента или интервала, PTS, не совпадающие с видео, …)
   останавливают работу с кодом выхода 2 и сообщением; ничто не исправляется
   молча.

</details>

<details>
<summary><b>Что делает каждая команда</b></summary>

- **Калибровка** (`calibrate`): гомография по ≥ 4 проверенным точкам на полу,
  а также вертикальный столбец камеры по ≥ 2 приподнятым опорным точкам сетки.
  Отложенные точки пола никогда не используются для подгонки и выводятся
  отдельно (в пикселях и метрах). Вырожденные, повторяющиеся, коллинеарные и
  нечисловые (не конечные) входные данные отклоняются. Гомография пола никогда
  не применяется к точкам в воздухе.
- **Анализ** (`analyze`): один полёт на каждый проверенный контакт, время
  отсчитывается от проверенного контакта (нулевой момент), даже если первая
  детекция появляется позже. Используются исходные PTS, идентификаторы кадров и
  идентификаторы сегментов камеры; склейки камеры исключаются, и полёты никогда
  не переходят через границу сегментов. Каждый полёт заканчивается на следующем
  контакте (перехвачен, а не принудительно приземлён), в проверенной зоне
  приземления (ограничение, а не измеренная координата) или на последнем
  наблюдении сегмента. Проверки по полу и сетке отбрасывают невозможные
  подгонки. Если полёт был перехвачен, точка на полу, которой он *достиг бы*,
  выводится отдельно как контрфактическая. Пропущенные детекции остаются null.
- **Рендеринг** (`render`): сверяет каждый декодированный исходный кадр с PTS
  треков, рисует предоставленные рамки игроков, кольца наблюдаемого волана
  (зелёные) и модели (оранжевые), а также вид корта сверху в раскладке
  6:4 (исходник/вид сверху). На кадрах со склейкой камеры наложение волана не
  рисуется. Аудиопакеты источника копируются потоком без изменений (без
  перекодирования), поэтому начальное смещение и пропуски исходного аудио
  сохраняются; рендеринг завершается ошибкой, если аудио нельзя скопировать в
  MP4 или меняется его тайминг. Shell-команды из имён файлов не строятся.
  Выходные файлы никогда не перезаписываются: рендеринг завершается ошибкой,
  если выходной файл существует или совпадает с источником, пишет во временный
  файл с уникальным именем и публикует его только после полной проверки
  декодированием.
- **Демо** (`demo`): генерирует полностью синтетический розыгрыш (две
  виртуальные камеры, склейка камеры, зашумлённые детекции с пропусками,
  тестовый тон) и запускает весь конвейер, включая отчёт о восстановлении
  синтетических эталонных данных.

</details>

<details>
<summary><b>Как читать результат</b></summary>

| Слой | Значение |
| --- | --- |
| `observed_pixel` | предоставленная детекция без изменений; null, если отсутствует |
| `human_review` | ваши контакты, зоны приземления и точки калибровки |
| `conditional_model` | физическая модель, подогнанная к наблюдаемым пикселям при ваших априорных значениях |
| `display_interpolation` | линии и маркеры, которые рисует только рендерер |

Скорости представляют собой начальную скорость подогнанной модели
(`model_speed_km_h`, отображается с округлением до 5 км/ч). Считайте их
приблизительными модельными значениями.

</details>

<details>
<summary><b>Ограничения</b></summary>

- Нет детекции волана и игроков. Детекции вы предоставляете в
  [формате треков](docs/schemas.md) (на английском); веса моделей не загружаются.
- Нет автоматического поиска контактов и уточнения их временных меток.
- Нет обученных плотных карт глубины, нет обученных меток ударов, нет автоматических решений IN/OUT.
- 3D-выход условный, а не измеренный. Низкая ошибка репроекции показывает
  согласованность с 2D-детекциями, а не независимое доказательство точности 3D.
  Результаты синтетического восстановления являются синтетическими.

</details>
